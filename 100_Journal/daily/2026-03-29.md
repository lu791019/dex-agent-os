## 學到什麼
- **Notion 字數 ≠ Python `len()`**：Notion rich text 上限 2000 是 UTF-16 code units，supplementary 字元（emoji、部分 CJK）佔 2 units。用 Python `len()` 切分會在邊界爆掉 → 必須用 UTF-16 編碼長度計算
- **安全邊距模式**：外層 chunk 留 100 字元 buffer（1900），內層才做精確切分。防禦式設計比精確計算更可靠

## 洞察 & 靈感
> 可轉化為內容素材的想法

- 「你的字串長度不是你以為的長度」— UTF-8 / UTF-16 / grapheme cluster 三種計算方式，在不同 API 會咬你一口。這是每個串接第三方 API 的工程師都會踩的坑（→ Threads / Blog）
- 安全邊距模式（buffer pattern）：與其追求精確卡在邊界，不如預留 5-10% 餘量。從工程延伸到時間管理、專案估時都適用（→ Threads）
