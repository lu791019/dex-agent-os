# 週六下午坐下來的那一刻，你的週末就結束了

## 核心論點
Side project 不是休息，它是你用熱情包裝的隱性加班——不刻意劃出「什麼都不做」的時間，你永遠只是換了一種方式在工作。

## 關鍵素材
1. **「不知不覺就坐下來了」的共感畫面**：週六下午原本打算放空，結果打開筆電「看一下」就寫了三小時 code。這不是意外，是大腦把 side project 歸類為「不算工作」的自我欺騙
2. **休息悖論：愈熱愛愈無法停下**：對技術有熱情的人最容易掉進這個陷阱——正因為 side project 是自己選的、沒人逼你，所以你連罪惡感都沒有，直到週一上班發現自己根本沒充電
3. **隱性加班的認知成本**：即使 side project 內容跟工作不同，大腦消耗的認知資源是一樣的。你以為換了跑道就是休息，其實只是換了一條賽道繼續跑
4. **「什麼都不做」需要刻意練習**：對創造者來說，空白不是自然發生的，而是要像排會議一樣排進行事曆。不排，它就不會出現
5. **自我檢測問句**：「你上一次真正什麼都沒做的週末是什麼時候？」——如果答不出來，就是該停下來的訊號

## 頻道適合度
- ✅ **Threads**：最適合。「不知不覺就坐下來了」這個畫面極度共感，主文丟出這個場景就能讓人秒懂，串文翻轉到「這不是熱情，是隱性加班」，結尾一句自我檢測問句自然引發互動。短文節奏剛好，不需要長篇論述
- ✅ **Facebook**：適合。可以用稍長的個人故事展開——從自己某個週六下午的經歷切入，帶出「我後來怎麼發現這個問題」，結尾開放提問容易引發同溫層討論，尤其工程師和創作者社群會很有感
- ❌ **Newsletter**：不太適合獨立成篇。觀點明確但素材偏薄，撐不起一整期電子報的深度。適合作為週報中「本週反思」的一個段落，搭配其他主題一起出
- ❌ **Blog**：不適合。這是觀點型而非方法論型的主題，缺乏步驟化的解決方案和足夠案例來支撐長文。硬寫會變成雞湯，違反風格原則
